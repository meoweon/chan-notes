## 1. 样本粒度与两种「泛化」的准确含义（跑前校准）

### 1.1 「每日一行」是什么，为什么作废

D028 时期的旧口径是：把 24 根 1h bar 压成一天一个样本，标签取「未来 24 根 bar 的已实现波动率在 50 币间取横截面中位数，再取 log」，输出**每日一行、约 2500 行**。这样设计是因为当时 E005 门控是一天一个开关，训练口径就去对齐日频输出。

代价是把 50 币 × 24 bar 的信息**在训练之前就压掉了**：模型从头到尾只见过「市场」这一个合成对象，从没见过「某个标的自己的价量形态」。它既不可能换一批币还可用，也不可能换周期还可用——被预测的实体在训练前就被聚合没了。按 D029 作废，原文按「作废不删」在 D028 与 [E005 §12](../30_实验/E005-frenzy门控升级.md) 留痕。

### 1.2 现在的粒度：1 bar × 1 标的 = 1 行

- 样本单位 `(bar_time, ticker)`，长面板；一行就是「某币在某根 1h bar 收盘时点的状态」。
- 标签是**这个标的自己**从 `t+1` 到 `t+H` 的已实现波动率（`H = label_horizon_bars`），取 `log`；**不做任何横截面聚合**。
- 特征只用该标的自身 OHLCV 派生，只到 `t`（含），滚动量一律 `shift(1)`。
- 输出同样是逐 (bar, ticker) 一个数。1h 实例下理论上限约 50 币 × 约 5.98 万根 bar，即**百万行量级**（各币上市时点不同，实际更少），远多于旧口径的 2500 行。

**为什么这是跨标的的物理前提**：模型学的是「价量形态 → 未来波动」的映射，样本里没有「市场」这个对象，也没有标的编号；换一批币，只要它们有同样的 OHLCV 字段，就能直接推理。反过来，若标签本身是横截面中位数，模型连「一个标的的波动」都没被要求预测过。

### 1.3 跨周期泛化：泛用的是协议，不是权重

2026-11-10 静态核查（只读源码、未运行上游脚本）结论：周期无关的是评估协议与方法论，周期相关的是日历常数与横截面结构。可迁移的是 QLIKE、`log` 目标、GK/RS 估计量公式、`shift(1)` 防前视、purge/embargo、train-only 标准化、多 seed、HAR 结构；不可迁移的是写死的日频假设。

外部参照把参数集中在配置里只是表象，日频字面量散落在多层：序列长度、rolling z 与横截面 rank 的窗口、按月 / 按年的日期偏移、vol-target 的年化因子。另有四类结构耦合：数据抓取不传 interval 即隐含日线；宏观变量按业务日前填，24/7 市场下「5 天」不再是一周；行业 rank / ticker 固定效应 / embedding / categorical 在跨标的设定下必须剔除（见 §1.4）；日历 `dow` / `DateOffset(months/years)` / 交易日索引要换成 bar 计数或 UTC 日历。

**一份训练好的权重必然绑定它的周期实例**（bar 长度、标签窗口、年化因子、宇宙、切分），换周期不能复用。E006 不做「一个模型全周期通吃」，而是把周期参数化后由同一份协议实例化——换周期 = 换一组协议参数 + 重新训练 + 重新评估，不复制代码、不从实现里继承日频常量。**先用 1h 训练**（§2 实例 A）；同一协议在 1h / 4h / 1d 上的结论是否稳定，属后续独立实验，不在本实验判定。

### 1.4 跨标的泛化：不是「把很多标的堆进训练集」

这是本次重定向最容易做假的一处。50 币一起训只叫 **pooled**，模型完全可以靠记住「BTC 波动低、小币波动高」拿高分，换一批币就失效。要让它成为可检验的能力，必须同时满足两个硬条件，且都写进冻结协议：

1. **禁止一切标的身份特征**：ticker id、one-hot、embedding、categorical、ticker 固定效应、行业/板块标签一律不进特征；不得用标的名做分组统计后回灌。可用的只有该标的自身 OHLCV 的因果派生量。同理，横截面量（当日全市场涨幅占比、行业 rank、`CSZScoreNorm` 之类按日在标的间标准化、VIX 类共同宏观）也不进——它们会让推理依赖「今天整个池子长什么样」，换池子即失效。
2. **固定留出标的组（leave-ticker-out）**：从冻结宇宙中划出一组币，**在所有折的训练里完全不出现**（含 IS 早停与超参冻结），只在 OOS 时段评估。留出组按上市时点、波动档位分层固定，划分结果写进 `protocol.json`，不得看结果调整。留出集同时是「未见标的 + 未见时间」，是双重外推；随机按 ticker 分组的 KFold 会破坏 PIT 纪律，不许用。

**外部参照恰是反面参照**：其 HAR、LSTM、LightGBM 三族都把 ticker 身份写进了模型结构（固定效应、embedding、categorical）；因此它虽是 `(date, ticker)` 面板，却**结构上不支持换标的**。按 D029，本仓与外部参照从「per-ticker vs 市场级」的对立，变成「形似而神不同」：粒度相近，但身份特征与验证方式相反。外部参照的 RV 估计量、QLIKE、HAR 尺度结构、防前视纪律因此反而更直接可借，唯独身份相关部分与带固定效应的 HAR 基线必须剔除（纯 pooled HAR）。详见外部参照笔记 §9。

## 2. 首个周期实例（实例 A：1h，不是模型定义本身）

为让「先用 1h 训练」有可执行落点，定义第一个实例；它只是 `protocol.json` 的一组取值，换实例不改动实验结论：

- bar 1h，24/7 UTC 日历，`bars_per_year` 按 365×24 计（年化因子随参数走，不写 √252）。
- **每个 bar 收盘都是潜在决策时点**，不再有「每日 UTC 00:00」的限制；标签为该标的未来 `H=24` 根 bar 的 close-to-close `sqrt(Σr²)`，取 `log`。`label_estimator` 主用 close-to-close；GK / RS 作并列诊断（外部参照称 range-based 效率高 7–8 倍属 **E2**，本仓未验证，验证前不替换主标签；要评估另开实验）。
- 特征只到 `t`，无横截面量、无标的身份（§1.4）。标签重叠：相邻行标签窗口共享 `H−1` 根 bar，重叠率 `(H−1)/H = 95.8%`；`purge_bars ≥ H`、`embargo_bars ≥ H`，均按 bar 计，不照抄上游 5/5 交易日。
- 输出频率：**每 bar 每标的一行**（`output_frequency=bar`）。旧的「日级一行」作废。
- 宇宙：`*USDT.parquet`，point-in-time 冻结，**跑前点验**（§3）。
- **横截面聚合不在此实例定义内**：日级化、横截面中位数 / 上分位 / 超阈占比等一律由消费方在训练完成后自行定义并冻结（D029）。

## 4. 特征与模型

- 特征块沿用 [E005](../30_实验/E005-frenzy门控升级.md) 单阶段稿已核验的四组（按 D028 迁入本文），窗口长度全部按协议参数推导，并**按 §1.4 剔除一切身份与横截面量**：① 158 聚合块（字段清单由 qlib `Alpha158DL.get_feature_config()` 导出冻结、pandas 复刻逐列对拍；窗口按 bar 数重设为 24/168/720 根 bar 三尺度，不沿用 `loader.py` 的 `[5..60]` 日线默认）；② HAR 尺度块（窗口按 `har_windows_bars`）；③ 绝对量块（**排除**涨幅 > 0.08 / 0.095 的占比及其平滑，不把 frenzy5 原料换皮放回）；④ 时段块（UTC 小时周期与分时段量占比）。**不再有「日期 × 标的 × 158 压成每日一行」这一步**；frenzy5 仅作诊断消融、不进主链路。
- 无量纲化：可用因果 rolling z-score（外部参照的因果 rolling z-score 那种，无需 fit、天然无泄漏、换周期只改窗口）；但它会抹掉「相对过去 N 根 bar 的水平」，对波动中枢漂移是利是弊须预注册定死，不得看结果择优。**不用** `CSZScoreNorm`（按日在标的间 z-score 是横截面量，违反 §1.4）。任何需要 fit 的标准化统计量只在 train 折计算（fit 只用训练折的纪律），且不得按 ticker 分别 fit。
- 模型：主模型 XGBoost 回归，LightGBM 作同时预注册的稳健性对照（结论并列、不择优，不一致判「不稳定」）；**不使用任何 categorical / embedding / 分组回归**。
- 基线（全部逐标的计算、纯 pooled、无身份特征）：persistence、HAR-RV 线性（1/24/168/720 bar 三至四尺度真实回归，**不带 ticker 固定效应**）、IS 历史中位数。超参在 IS 一次早停确定并写入产物，不在 OOS 调。
- 种子：`seed_count ≥ 5`，报告预测值的种子间标准差与排序稳定性。

## 5. 切分、评估与判据（预测层，用途中立）

- **绝对日期写死**，不从数据末尾相对推导：IS `2020-01-01 ~ 2023-12-31`（训练、早停、冻结超参），OOS `2024-01-01 ~ 2026-10-31`（只在最终判定用一次）。
- 标签重叠：`H=24` 时相邻样本共享 23/24 根 bar。逐月 purged walk-forward，每月模型只用「月起点 − `purge_bars` − `embargo_bars` − `H`」之前的数据；**禁止随机 KFold**，禁止按 (bar, ticker) 随机打散切分（同一时刻的 50 币必须整块进同一侧，否则横截面泄漏）。
- **留出标的组**在所有折训练中完全不出现，只在 OOS 时段评估；划分在协议冻结时一次性写死（§1.4）。
- loss：QLIKE 与 log 空间 MSE **双指标**（外部参照的指标实现；其横比里 GARCH 在两种 loss 下排序翻转，故「同时优于」是必要设计）；OOS R² vs HAR 只作报告项。指标按 (bar, ticker) 计算，**同时报告三个口径**：全体 pooled、逐标的分布、留出标的组。标的间加权按 §3 冻结规则。DM 检验若使用，loss 必须与准入门槛一致并作多重比较校正，否则**不用**。
- **成功判据（本实验唯一判据）**，在冻结协议下须全部成立：
  1. 候选模型的 QLIKE 与 log 空间 MSE **同时**优于 persistence 与纯 pooled HAR-RV 两个基线（全体 pooled 口径）；
  2. **跨标的**：在固定留出标的组上，双指标仍**同时**优于两个基线；逐标的分布不得由少数币主导；
  3. ≥5 seed 的预测排序稳定；产物可复现（同协议重跑得到同一份预测）。
- 第 2 条是按 D029 由「跨标的泛化」目标推导的**加严项**，不是对旧判据的放宽；若用户否决该加严，须在跑前明示并改预注册，不得看结果后取消。
- **失败**：任一条不满足即判阴性并如实记录。**阴性不影响是否开展下游应用**——下游各有独立判据，不因预测层阴性就禁止检验其经济价值，也不因预测层阳性就推定其有价值。
- **明确不设的判据**：组合夏普、开机率、换手成本、相对 frenzy5 的 A/B、vol-target 净 Sharpe、任何横截面聚合后的指标。写进来就是把用途又绑回来了。
- 与上游成绩表**不逐值对齐**（D026）：本仓内部口径自洽是底线，`protocol.json` 冻结后自有模型之间必须同口径比较；外部参照的成绩表只是「作者当时得到过什么」的备查文本，不作基准。**无美股预演**（D027）：协议实现若有 bug 将直接在 crypto run 上暴露，缓释为跑前冻结协议、防前视硬断言、基线与双指标先在 IS 内自检口径自洽。

## 6. 产物契约（下游怎么读）

`exp/E006-vol-forecast/` 下冻结：

| 产物 | 内容 | 给谁用 |
|---|---|---|
| `protocol.json` | §1.4 / §5 全部协议参数 + 标签 / loss / 切分绝对日期 / 基线 / 种子数 + 冻结宇宙名单 + **标的间加权规则与留出标的组划分** | 全部下游，只读 |

## 7. 假设与预期反例

- H1：在冻结协议下，树模型能同时打赢 persistence 与纯 pooled HAR-RV（预测层有信息）。
- H2（跨标的）：留出标的组上优势显著缩小甚至反转——这是最可能的先验结果，因为不同币的波动中枢与微观结构差异大，而 §1.4 又禁止用身份特征吸收它。若发生，如实判「泛化不成立」，不得靠加回 ticker 特征补救。
- H3（预期反例，来自上游阴性证据）：即使预测层赢，下游组合经济价值仍可能为零——外部参照 LSTM 相对 HAR 的样本外 R² 有两位数百分比提升，扣 5bp 成本后净 Sharpe 几乎没有改善；点预测最差的 GARCH 净 Sharpe 与 LSTM 相当而换手远低（外部参照的结论）。**这条只作为「不要把预测层胜利写成应用价值」的纪律，不在本实验判定**。
- H4（预期反例）：ML 只是重发现 HAR——外部参照的树模型重要性排名显示，RV / GK 滞后项远高于宏观 / 日历特征（E2 为作者解读）。故报告「分数对 HAR-RV 取残差」的诊断量，但**不据此改本实验判据**。
- H5：标签错位 / 打乱后预测仍有优势，或打乱 ticker 标签后指标变化 → 判口径泄漏或身份依赖，实验作废重查。

## 8. 停止条件与已知风险

- 一次逐月 walk-forward + 一套固定超参即停；消融固定为「仅 158 聚合 / 仅 HAR 尺度 / 158+HAR / 158+HAR+绝对量+时段」四组 + 一组 `+frenzy5` 诊断，不追加第二网。不因结果好坏增删特征块、换标签、调超参、改留出组划分。若阳性，另开实验独立复核。
- 风险：① **样本量大不等于信息量大**——百万行但标签重叠 95.8%，有效独立「波动波次」仍可能只有几百个；树模型在高度相关样本上会给出虚低的验证误差，故 walk-forward 与留出组双重约束不可省；② **标的间不平衡**（§3），长历史币主导拟合，须冻结加权规则；③ 无量纲特征预测有量纲标签、波动中枢漂移会让 IS→OOS 映射失效（E001 同机制），`log` 目标 / HAR 块 / train-only 标准化只能缓解，且禁身份特征后无法再按币校准中枢，这一条比旧口径更硬；④ **跨标的与跨周期叠加**：不同周期实例的波动中枢、微观结构不同，不得把 1h 权重直接用于 4h；⑤ 币池成分漂移与 point-in-time 纪律（§3）；⑥ 外部参照 README 的绩效、GK 效率倍数、SHAP 解读均为 **E2**，本仓未复算；⑦ qlib 装的是 PyPI 0.9.7，与 vendor pin `5435523` 不是同一份代码，只借字段清单，不接其 DatasetH / 回测链路，且缺 `cn_data`；⑧ 1h 24/7 日历与默认日线 calendar 不一致，pandas 复刻只与 qlib 字段清单逐列对拍，表达式语义等价性靠抽样验证；⑨ 所有模型在高波动期倾向低估 RV（第三方 E2），恰是下游最需要识别的区间；⑩ 逐 (bar, ticker) 产物体积远大于旧口径，须落 `out/` 并压缩。
- 第三方结论（Branco / Rubesam / Zevallos 2024，*Journal of Empirical Finance* 78:101524）均为 **E2**，只作先验不作本仓结论。
