# 专题：合成指数与阈值口径

一个"市场背景"特征族看起来只是 8 列数字，实际上它的口径由**篮子成员、在场阈值、归一化方式、OHLC 来源**四件事共同决定。这四件事任何一件变了，同名文件可以给出方向相反的结论，而下游模型分数不会报错。本文写可迁移的规律，本次实例的判定原文在 D037 与 D038。

数据伪影（假零量、地板标签）那一类教训见 数据伪影与损失污染；本文讲的是**聚合口径**，两者不混用。

## 结论（E1）

### 1. 绝对计数阈值是时代残留，换篮子就静默改口径

`min_stocks=30` 是 50 只 A 股时代定的数。它有两种失效方式，且都不报错：

- **篮子比阈值小** → 全部时刻被筛掉 → 旧代码崩在 `close.iloc[0]`，抛 `IndexError: single positional indexer is out-of-bounds`，报错里完全看不出是阈值问题（实测 21 币、10 币均如此）。
- **篮子随时间增长**（新币陆续上市）→ 早期"当时几乎全员在场"的时刻因为绝对数不够被整段抹掉。实测 69 币池 + `min_stocks=30` 会把指数起点从 2020-01-06 推到 2020-09-29，事件表里 1,118 条（2.5%）拿不到市场上下文（D037 理由 3）。

规律：**阈值要么相对化（按当时已上市成员的比例），要么保留绝对值但加显式守卫 + 丢弃行数审计输出**。"默认值能跑"不等于"默认值对"。

### 2. 指数的起点和量级是口径指纹，不是数据属性

同一个 `data/bars/1h/_MARKET.parquet`、同一个时间戳 `2026-10-31 23:00`，换篮子前 close = **8,051.26**（六年涨 7 倍），换篮子后 = **302.90**（同期跌 70%）。市场没变，变的是"这一篮子包含谁"。

规律：**合成指数必须把篮子成员、阈值、聚合方式、sha1 一起记进决策记录**，否则事后无法判断两根曲线是否同源。覆写式保存（`store.save` 是整文件覆盖）尤其要先备份。

### 3. 归一化后取中位数带"上市即高点沉没"偏置

每个成员除以自身首根 bar 归一到 1.0。2021 年后高位上线、随后阴跌 80–95% 的币，归一值长期停在 0.05–0.2，会系统性压低中位数。所以**篮子扩容不是中性操作**：加进一批新币，指数可能从涨 7 倍变成跌 70%，而这不代表市场变差。该偏置已在 D037 风险②登记，本次只修阈值、不改公式。

### 4. 合成 OHLC 只支撑 close-based 指标

`_MARKET` 的 `volume` 恒为 0，`open` = 上一根 close，`high/low` = `close × (1 ± 近3根平均|涨跌| × 0.3)` 再钳位。于是：

- 只用 close 的 6 个特征（`ret5/ret20/above_ma20/above_ma60/ma20_slope/rsi`）不受影响；
- 依赖 high/low 的 `mkt_atr_pct`、`mkt_range_pos20` 失真——编出来的振幅带极窄，实测事件表里 `mkt_range_pos20` 取值 **−4.51 ~ +6.76**（本该是 0~1 的区间位置）。

规律：**range-based 估计量（ATR / GK / Parkinson / RS）一律不能用合成指数算**，只能用逐标的真实 OHLC。这条早有登记，见 E005 §门控 与 `scripts/build_market.py:31-35`。

### 5. "按目录取全部标的"会跨市场泄漏

`data/bars/15m/`、`1h/` 里同时躺着 69 个 7×24 的 USDT 币和 50 只每天只有十几根 bar 的 A 股，且**币存 UTC naive、A 股存 CST naive**。默认篮子取"目录内全部非 `_` 代码"时，在场数会随 A 股开收盘在 69 ↔ 119 之间跳，中位数样本集随之切换——等于把"现在是不是 A 股交易时段"泄漏进加密的市场上下文。

规律：**聚合前必须按市场过滤宇宙**，不能靠目录边界。本仓的过滤口径在 `chan_notes/gates/base.py:21-33`（`_MARKET` 恒排除、crypto 认 `USDT` 后缀、ashare 认 `sh./sz.` 前缀）。

### 6. 复现不出来 ≠ 可以假装连续

对 {69 币 / 30 币 / 50 A 股 / 119 混池} × {min_stocks 1~50} × {mean / median} × {ffill 8 / 无限} 逐组对撞旧文件，逐值吻合率最高 **0.0017%**，无一复现。结论只能是"现存产物出自当前代码之外的另一套口径"，处置是**备份 + 重跑 + 显式宣布新旧不可比**，而不是挑一个最接近的参数假装连续。

### 7. 改口径的代码，要先证明旧口径零漂移

修阈值这类改动，验证方式不是"新参数能跑"，而是**用旧参数 dry-run 重算，与已落盘产物逐值对撞**。本次实测：69 币 + `min_stocks=4`，1h 59,944 行、15m 239,775 行，时间轴逐值相同，OHLC 最大绝对偏差 **0.0**。

## 反例与边界

- **`--min-frac` 与 `min_stocks=4` 不等价**：相对阈值会把起点提前到篮子第一个成员上市那天（D037 的锚点 2020-01-06 是"当时 cnt=4"量出来的），两者给出的指数起点不同，**不可混用**。D037 冻结口径的复现命令仍然是 `--min-stocks 4`。
- **30m 不能顺手重跑**：现存 30m 指数覆盖 2020-01-02 起，而现存 A 股 30m bars 最早 2023-01-03，重跑会直接删掉三年指数（D037 决策 5）。本次 30m 文件 sha1 未变。
- **默认值 30 本身没改**：改的是"超篮子/筛空时硬失败 + 可选相对阈值 + 审计输出"。50 A 股与 69 币两种真实篮子的默认行为逐值不变，避免又一次静默改口径。
- **混池的实际影响要量，不要吓**：1h 上"69 币池"与"119 混池"的中位数曲线实测几乎重合（中位数仍由币决定），所以混池的危害主要是**口径不可解释 + 时区语义混装**，不是曲线一定大幅偏移。泄漏是否成立要按周期实测。
- **本文不覆盖真实指数**：若改用交易所官方指数或沪深300 真实行情，第 3/4 条偏置与失真不适用，但第 1/2/6/7 条（阈值、指纹、复现、零漂移验证）仍然适用。
