## 1. 预注册（运行前填）

### 问题

E011 在 A股 上判了两个候选 `loses_to_armed_traditional`：一条 `ewma_gk_armed`（λ=0.94 的 EWMA 吃 Garman-Klass，再按「标的×小时」去季节）QLIKE 0.4035，压住 LightGBM 3.11698 与 XGBoost 59.8554。那句话当时被限定成「A股 上如此」，因为 A股 有两只脚踩在季节性上：日内时段剖面极差 **0.938 个 log 单位**，而冻结的 HAR 基线连一个时段变量都没有。

crypto 是主线市场，也是这套结论真正要服务的地方。它有三个结构性不同：24/7 没有交易日边界、时段剖面只有 A股 的约 43%、而且 E008 的判定口径**已经没有地板行**（`volume>0` 剔除后 `floor_rows = 0`）。同时它有一个致命的相似：候选对 persistence 的 QLIKE 优势只剩 **0.4%**（0.74797 vs 0.75112）。

所以本实验要回答的是：**把 E011 那套四档参照阶梯原样搬到 crypto，武装传统模型还打不打得两个候选**。这直接决定 E005/E008 那条「双指标优于基线」的主线阳性要不要改写成「仅对 persistence/HAR 阳性」。

### 假设

- H1：A股 的败因主要是「基线可武装」——crypto 季节性弱，武装层拿到的增益小，候选在 QLIKE 上至少能与 `ewma_gk_armed` 进入同一量级。
- H2：候选对裸版 `ewma_rr`/`garch_rr`/`ewma_gk` 的 QLIKE 一侧仍然输或擦线（因为 crypto 的 persistence 本来就是强基线，lag1 自相关中位 0.671），MSE 一侧继续明显赢。
- H0（要能接受）：crypto 上也输。那样主线阳性被降级为「只对 persistence/HAR 阳性」，**照原样写进结论，不做补救性实验**。

### 判据（形态与 E011 §1 逐字同级，口径不放宽）

- **C1′（主判据）**：候选（lgbm 或 xgb 至少其一）在 **45 只训练币逐标的等权**口径上，QLIKE 与 log-MSE **同时**优于三条武装参照 `{ewma_gk_armed, har_garch_rv_armed, har_hour}`。
- **C2′**：候选对 `{ewma_rr, garch_rr, ewma_gk, har_garch_rv, har, naive, r3_calendar}` 双指标同时占优的条数（只数数，不据此放宽 C1′）。
- **C3′**：硬自检 S12-1…S12-7 全过，且 E008 六件冻结产物 + 本 `protocol.json` 跑后 sha256 不变。
- **bootstrap（报告项，决定写法）**：标的簇重抽 1,000 次、seed 42，差值 = 候选 − 参照（负 = 候选更优），报点、95% CI、是否跨 0、候选更差的币数 /45；QLIKE 与 MSE 各一份。
- **三分类裁决**（必须写明是哪一类，不得用「阳性/阴性」掩盖）：
  - `beats_armed_traditional`：C1′ 点比较过 **且** 6 项 bootstrap CI 全不跨 0 **且** 无一项「>22/45 币更差」 **且** 与留出组、pooled 两个报告口径无反号 **且** 6 项 QLIKE 差距均不满足「>50% 来自 ≤5 行」；
  - `loses_to_armed_traditional`：C1′ 点比较即输；
  - `indistinguishable`：其余全部情形。
- **不是判据**：不设「必须赚钱」；vol-target / 净 Sharpe 只作量纲自洽诊断。

### 口径与伪影处置（跑前写死）

- **单口径 + 三条稳健性替代 A/B/C**：crypto 判定口径无地板行，故不设三口径；把 E011 用 arm-C 承担的稳健性角色换成 ① 币簇 bootstrap CI 与更差的币数、② 留出 5 币等权、③ 行级 pooled。三口径若与判据口径反号，该侧降级为 `indistinguishable`，**不挑口径**。
- **伪影对称规则（D042 第 3 条）**：判据口径下每行对差距的贡献 = `gap_i/(45·n_ticker)`；若某条 QLIKE 比较的差距有 >50% 来自不超过 5 行，该条 QLIKE 侧一律写「不可分辨」并列出这 5 行归属（近零 gk bar 之后 / 断档之后 / 高波动尖峰）。**两侧通用**。
- **下尾披露**：逐臂报 `min(y_pred)`、0.1% 与 1% 分位、单行最大 QLIKE 贡献份额。
- **D041 相邻行披露**：照报，预期两项均为 0 行 / 0.0%，仍须自证。
- **跨市场可读性约束**：与 A股 并列时**只引用 E010 arm-C（80,272 行）**，不得拿 A股 arm-A（含 42 行地板，MSE 0.285）与 crypto（MSE 0.175）并排说「A股 更差」。
- **断档处理**：缺 bar 不回填（E008 语义，占比 0.11%）；`naive`/EWMA/GARCH 一律按「上一根有效行」递推。

### 跑前预期（写下防事后编故事）

1. 武装层增益小于 A股 但**不为零**（逐币剖面极差中位 0.411 vs 0.938，约 43%）→ 预期 `ewma_gk_armed` 相对 `ewma_gk` 的 QLIKE 改善在 A股 那 −40% 的三分之一量级以内。若接近 A股，须先查 `f` 是否越界再谈结论。
2. 不会出现天文数字 QLIKE（`floor_rows = 0`），naive 0.7511 是可信读数 → 本实验是两侧第一次在**同口径干净度**上比较。
3. 候选对 persistence 的 0.4% QLIKE 擦线大概率翻不过来：只要裸版 EWMA/GARCH 落在 0.70~0.75，C1′ 就不过。
4. MSE 一侧候选预期仍最优（0.1749 vs 0.2398/0.2074），预期复现「MSE 赢、QLIKE 输」的同形结论。
5. ≤5 行主导规则的触发率预期**显著低于** A股 的 18/18（差距是百分之几而不是几个数量级，天然分散）。**若 crypto 也大面积触发，那说明这条规则是本仓 QLIKE 口径的通病，不是一字板特有**——这本身是有价值的元结论。
6. **若 crypto 也输，那是本实验最有价值的结果**：主线 E005/E008 的阳性须改写为「仅对 persistence/HAR 阳性」，照原样写，不做补救实验。若 crypto 赢而 A股 输，结论限定为「武装基线的优势来自可武装的日历结构」，并必须同时披露两市场口径差异，不得写成「crypto 已确证模型有效」。

## 4. 结论

**一句话裁决：在 crypto 上，把传统模型喂饱之后，两个机器学习候选依然打不过一条 `ewma_gk_armed`（λ=0.94 的 EWMA 吃 Garman-Klass + 去季节）——而且这一次不是数据伪影，是 45 只币全体同向的真实劣势。**

1. **裁决形态 = `loses_to_armed_traditional`（两候选同形）**。按预注册三分类，C1′ 点比较即输，不进 `indistinguishable`。输的是 QLIKE（0.748 vs 0.580），MSE 一侧候选大幅领先（0.175 vs 0.256，45/45 币同向）。
2. **两把尺子给出相反方向，且这一次两侧都稳健。** QLIKE 对低估波动是指数罚，EWMA 的条件反应快；树模型把预测压得更平滑，0.1% 分位比 EWMA 低 0.4~0.8 个 log 单位，被罚掉的就是这一块。「谁更好」在本实验口径下没有唯一答案，取决于风控函数长什么样——这句话必须和裁决一起写。
3. **A股 的 E011 结论不能被当作「ML 无用」的证据，crypto 的才可以。** A股 18/18 比较触发 ≤5 行主导（一字板地板值），crypto 只有 2/18、且都在差距 0.4% 的「vs persistence」上。这是本仓第一次拿到一个**没有伪影遮蔽的 QLIKE 阴性**。
4. **主线表述须改写（下一步 1）**：E005/E008 的「双指标优于双基线」在 crypto 上只覆盖 `naive`/`har` 这两个弱参照；面对同信息集的传统模型，QLIKE 一侧为负。按 D042 第 1 条，参照组最低要求现在在**两个市场**都成立，不再是单市场观察。
5. **候选真正的、跨市场稳健的增量只有一处：log-MSE。** A股 0.175 vs 最好参照 0.180~0.205；crypto 0.175 vs 最好参照 0.1946。幅度约 10%，两侧、两候选、逐币 CI 不跨 0。若下游（波动率目标化仓位）用 MSE 型损失，模型有位置；若用 QLIKE 型（不对称惩罚低估），一条 EWMA 就够。
6. **不做补救实验**（预注册停止条件）。不重调 λ、不换 GARCH 阶、不改武装定义、不重训候选。上面第 3.8 节「λ=0.84 对基线更有利」是**披露**，不是重跑的理由——它只说明本次阴性偏保守。

## 5. 局限

（跑前写明的 1~6 条继续有效，7~9 为跑批过程中新登记）

1. **候选侧零训练 → 无法归因到候选**：本实验只动基线，若结论翻转，只能说「参照组够强」，不能说「模型不行」或「模型行」。
2. **已见数据复判**：OOS 段与 E005/E008 判定同段，不构成独立确证。
3. **武装键只用 hour-of-day**：实测 dow pooled 极差 0.2543（周末效应）未纳入武装，等于故意给基线留了没吃完的信息；若要吃完须另开实验。
4. **断档 0.11%**：缺 bar 不回填，`naive`/EWMA/GARCH 按上一根有效行递推，断档跨度可达数小时——GARCH 的条件方差在此处语义上被「拉平」，登记为已知偏差（crypto 侧无地板行，但断档行仍会进 ≤5 行主导归属）。
5. **单市场单周期**：crypto 只有 1h 一档，不能外推到 5m/30m；A股 30m 亦未测。
6. **GARCH 规格固定**：(1,1) + Normal + Zero/HAR 均值，不扫阶数、不换 t 分布（E011 已冻结该选择，换规格 = 新实验）。
7. **新登记：预注册没覆盖「上市晚于 cutoff 的币」**。crypto 50 只里有 4 只（JTO/JUP/STRK/TON）在某几折的 cutoff 之前历史不足或为 0，而 E008 的四件候选全是池化/横截面估计量，照样能给出预测 → 判定行集里出现了逐币基线**结构上不可算**的行。处置（写死在代码里、对所有臂对称）：
   - `nobs = 0` 的币-折（JUP/2024-02、TON/2024-03 落在判定行集内，共 **378 行 = 判定行集的 0.031%**）→ 该行对**所有臂一并剔除**，保持配对；剔除集合必须逐条等于 `baselines_meta.json:har_lag_no_fit` 中 `nobs_before_cutoff == 0` 的币-折，否则 `evaluate.py` 硬停。
   - `0 < nobs ≤ 528` 的币-折（JTO/2024-01 有 518 行、STRK/2024-03 有 175 行，共 1,183 判定行 = 0.109%）→ HAR 均值项按**最长可辨识前缀**退化（`[24,120]` / `[24]`），arch 硬约束 `maxlag < nobs` 不可绕过。这让被比较对象在这些行上信息更少，方向对候选**有利**；每条退化都强制跑 S12-5 对拍（4 次，最大相对误差 4.2e-14），并做了「整只剔除 JTO+STRK」的敏感性（形态不变，见 §3.8）。
   - 预注册的「不缩样本」条款在此被违反 0.031%，是设计缺口的必然结果而非挑选；判据、口径、参照集合、λ、bootstrap 一项未动。
8. **新登记：cutoff 取整差一根 bar**。E011 的 `searchsorted(cutoff, side="right")` 在 A股 无影响（cutoff 落在闭市时段），crypto 是 24/7 小时线、cutoff 整点必有 bar → 会把 cutoff 那一根算进估计样本，与 `fold_masks` 的 `bar_time < cutoff` 不同语义。已改 `side="left"` 并在代码里加了越界硬停（§7 第 3 条）；全量跑批是在修正后重跑的。
9. **新登记：`rr` 侧 λ 网格数值不可用**。单条零收益 bar 后 `h` 塌到 `1e-300`、`to_log_sigma` 落到 −345，一行就能把 OOS 全程 QLIKE 顶到 6.9e+291（§3.8）。判据用的 `garch_rr` / `ewma_rr` 不受影响（判定行集不含那批早期行，读数 0.542 / 0.620 有限），但「λ 敏感性」这一报告项在 `rr` 侧只能读 MSE 列。
