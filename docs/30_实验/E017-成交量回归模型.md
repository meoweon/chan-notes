## 1. 预注册（运行前填）

### 问题

用户选定「借 DCKD 思路不借代码」：在本仓框架、用 crypto 69 USDT 1h 数据训成交量**回归**模型（预测下一小时 log1p 成交量，方向由预测值 vs 当前值导出），标签用本仓环比口径。**其 OOS 方向准确率能否超过 E014 最强零训练基线（a5_ma24_revert）至少 +2pp，且 balanced accuracy 更高、两口径同向？**（用户终极目标 >70%；E014 已判 70% 非平凡，本实验只问「模型是否比基线多学到方向信息」。）

### 假设

- H1（跑前预期，E3，可证伪）：pooled LightGBM 的特征集嵌套 a5 规则（当前值 + MA24 都在特征里，树可按币切），还能吃到更多滞后 / 日历 / 收益率信息，OOS 逐币等权 acc 落 **63~66%**（Δ +0.6~+3.6pp）；到 70% 概率低。
- H0（必须能接受的零假设）：Δv ≤ 0——默认参数树模型在这份数据上学不到超过一条 MA24 规则的方向信息。照实写阴性，**不调参、不补救**（D044 冻结）；「70%」在此特征集下不可达，换特征 / 换标签属另立预注册。

### 判据

记（跑前写死，门槛与披露同一表达式，D044 第 2 条）：

- `Δv = eq_acc_OOS(m1, volume) − eq_acc_OOS(a5, volume)`；`Δa` 同理 amount 口径。基线值**不手抄**：跑前从 E014 脚本产物 `out/metrics_summary.json` / `out/amount/metrics_summary.json` 全精度读出、冻进本协议（E014 已报约值：a5 volume 等权 0.62382 / pooled 0.62375 / bacc 0.63164；amount 等权 0.62334）。
- **C1 阳性** ⇔ `Δv > +0.020` **且** `Δa > +0.020` **且** `eq_bacc(m1,volume) > eq_bacc(a5,volume)` **且** 两口径各自 `pooled_acc(m1) > pooled_acc(a5)` ⇒「回归模型学到方向增量」。
- **C1 阴性** ⇔ `Δv ≤ 0` ⇒「默认参数回归在此特征集下无方向增量」，照实写，不补救。
- **其余一律「边际 / 不可分辨」**（含 0<Δ≤2pp、双口径劈叉、bacc 不更高、pooled 反向）：不进入蒸馏、不做补救实验。
- 若 volume 口径等权与 pooled 同时 ≥0.700，额外标注「达成用户 70% 目标」；分居两侧按 D039 写「口径敏感」。
- **C2 报告项（不进判据）**：幅度 log1p MAE / RMSE vs persistence（E014：等权 0.41653 / 0.54410，方向与幅度是两个问题）；混淆矩阵、precision / recall / F1（up 为正类）、逐年（2024/2025/2026）、逐币分布（中位 / 极值 / ≥70% 币数）、逐币 Δacc 正负币数与币簇 bootstrap 95% CI（10,000 次、seed 20261110，只作报告）；feature importance（gain）——若赢，不能排除「只是多了收益率信息」，严格归因需消融，属后续实验。
- **C3 硬自检**：
  - S1 数据冻结：跑前 69 个 bars 文件 sha256 清单与 E014 `protocol.json` inventory **逐项相等**（不等 = 数据被并发会话改动 → 即停、报告，不擅自重基线）；跑后复验不变。
  - S2 尺子同源（D042 第 5 条）：`import` E014 `baselines.py` 的 `build_pairs` / `judgment_mask` / `metrics`，重算 a5 / a6 / a7 的 OOS 等权 acc、pooled acc、等权 bacc 与 E014 落盘全精度值差 **≤1e-9**；有效对总数与判定行集行数同 E014 产物逐位（3,136,609 / 1,686,328）；persistence 幅度 MAE / RMSE 重算同 `level_baselines.json` ≤1e-9。
  - S3 防前视：`test_no_lookahead.py`——扰动 t+1 及以后的 volume / amount / close，t 行 21 维特征逐位不变；训练对 `max(next_t) < 2024-01-01 ≤ min(判定行 t)`（代码断言 + 测试各一处）；特征全部 lag / shift / rolling 构造。
  - S4 覆盖与 NaN：判定行集上 21 维特征 NaN 数 == 0（硬断言；rstd24 与 ma24 需要同样的 24 根前置有效 bar，结构上同边界）；训练侧 warmup 剔除数逐币落盘；OOS 判定行中 coin 类别未见于训练集的行数 / 份额 / 归属落盘，并给**剔除 unseen 币的敏感性 Δ 读数**（报告项，D045 第 4 条）。
  - S5 复跑验 sha1 逐位一致（两遍；LightGBM 固定 `random_state=0` / `n_jobs=4`）。
- 模板强制条款适用性：D041 两条（地板邻域披露）不适用——非单 bar 已实现波动率、无 QLIKE、`volume>0` 过滤后无地板值；D042 第 3 条（QLIKE 倍数）不适用；D043 第 3 条（格子稀疏）本实验无格子臂，a7 稀疏引用 E014 已测 6.71% ≤ 20%；D044 第 3 条不适用；D045 第 6 条（searchsorted 边界）不适用——无估计窗搜索，IS/OOS 用严格不等式（S3）。
- 停止条件：单次跑完即停；**不调参、不换特征、不补救**；墙钟上限 30 分钟，超限记录并停；S1–S4 任一硬断言失败即停、不产出判定。

### 数据

- 来源：`data/bars/1h/` 全部 **69 个 `*USDT.parquet`**（不含 `_MARKET`、不含 A股），区间随上市 ~ 2026-11-08，与 E014 同一冻结清单（S1）。
- 字段：`time / close / volume / amount`。主口径 `volume`；`amount` 同配方再训一遍作稳健性（E014 两口径八臂排序完全一致）。
- 有效性：与 E014 逐字同口径——双端 `volume > 0`（amount 口径用 `amount > 0`）、原始时间戳差恰好 1h、平局剔除；直接 `import` E014 `build_pairs`，不自写第二套（S2）。
- 数据可得时点：特征全部 ≤t（lag / shift(1) / rolling 压缩有效 bar 序列）；日历特征取目标 bar 的 UTC 小时 / 星期（日历在 t 已知）；标签为 t+1 已实现值。

### 切分

- IS 训练对：`next_t < 2024-01-01` 且 21 维特征全 finite（warmup 剔除逐币落盘）；OOS 判定行集：E014 共同可评行（`t ≥ 2024-01-01`、inertia_ok、ma24 / ewma94 finite），**逐行继承，模型与基线在同一张考卷上比**。
- 无验证集、无早停：默认 100 棵树冻结（D044），不存在用 OOS 选迭代数的通道。
- 特征 / 训练只用 IS；无任何 IS 统计量之外的全样本拟合。

### 模型与特征（跑前写死）

- 学习器：`LGBMRegressor`（lightgbm 4.7.0，venv 已有，**零新增依赖**），**全默认超参**；唯一非默认：`random_state=0`、`n_jobs=4`（确定性）、`verbosity=-1`（日志）。目标 = `log1p(next_vol)`，L2 损失。
- 方向导出：`ŷ > log1p(vol_t)` ⇒ up；持平归 down 并披露计数（连续输出预期 ≈0）。
- 两臂：`m1_volume` / `m1_amount`，同配方各自训练（pooled 全币混合，coin 作 categorical）。
- 21 维特征（col = 当前口径的 volume 或 amount；压缩有效 bar 序列上计算）：

| 组 | 特征 | 数 |
|---|---|---|
| 当前与滞后 | `log1p(col)` lag 0,1,2,3,6,12,24 | 7 |
| 均值回归 | `log1p(rolling_mean(col, w).shift(1))`，w=6,12,24（min_periods=w） | 3 |
| EWMA | `log1p(ewm(col, α=0.06, adjust=True).mean().shift(1))` | 1 |
| 收益率 | `close.pct_change()` lag 0,1,2,6,12,24 | 6 |
| 波动 | 收益率 rolling(24).std()（含 t） | 1 |
| 日历 / 身份 | 目标 bar UTC hour、dow、coin（均 categorical） | 3 |

- 参照组（D043 第 1 条两档齐）：E014 八臂在案——同信息集传统参照 a5 / a6（成交量自回归），日历武装参照 a7（币×小时查表）；判据对象 = 最强臂 a5。S2 重算对拍，不引用手抄数。
- 晚上市 / 零历史币（D045 第 4/5 条）：pooled 模型对训练中未见 coin 走 categorical 默认分支、照常预测，**不剔行**（基线侧在 E014 判定行集上本就全可评，无不对称 NaN）；unseen 行数 / 份额 / 归属落盘 + 剔除敏感性读数（S4）。
- **蒸馏本期不做**：① DCKD 式 KL / 关系蒸馏需 torch 系新依赖，须用户另行授权；② 蒸馏以回归臂先证明方向增量为前提——C1 阳性才另开预注册。用户选项中的「可选蒸馏」在此显式推迟，授权门可否决。

### 成本与成交

- 不接实盘、无成交假设。计算：IS 约 145 万对 × 21 特征、100 棵默认树 × 2 口径，预计分钟级；上限 30 分钟。只读 bars、不写 `data/`；并发披露：另一会话在推进 E015 / E016，本实验 CPU 分钟级、不抢长任务。

### 样本量与检验

- IS 训练对约 145 万（精确数跑时落盘）；OOS 判定行 1,686,328（E014 冻结）。C1 是跑前写死的描述性判定，不做假设检验；逐币 Δ 分布与币簇 bootstrap CI 作报告项，防等权均值被少数币拉过线。

### 预期反例

- Δv ≤ 0（H0 成立）：方向信息已被一条 MA24 规则榨干，接受阴性并关闭「默认参数回归」这条路；是否换特征时间尺度 / 标签语义另立预注册（特征尺度属协议层，不在本实验现场改）。
- IS acc 高而 OOS 低：过拟合，照实报，不补救。
- 双口径劈叉或新币上显著差：按判据写「边际 / 不可分辨」，披露归属。

- 尺子：`import` E014 `baselines.py` 的 `build_pairs` / `judgment_mask` / `is_fit_mask` / `metrics`，判定行集与指标函数与 62.38% 那个锚**同一个表达式**；基线值从 E014 产物全精度读出冻进协议（`baseline_snapshot`），不手抄。
- 与预注册的偏差（**共三处，全部记录**）：
  1. **协议重冻 `E017-1.0.0` → `E017-1.0.1`，发生在零判定数字窗口内（D044 第 4 条）**：预注册 S4 把「判定行特征必全 finite」写成结构性推断（原文以 `rstd24` 与 `ma24` 同边界为例，隐含「lag 类特征都需要 24 根前置有效 bar」）——这一条**错了一根 bar**：`ret_lag24 = ret.shift(24)` 需要先有 `ret[i-24]`，即 `close[i-25]`，比 `ma24` 深一根，于是 4 个 2024 后上市的币（JUP/RENDER/STRK/TON）各有 1 行判定行（有效序列位置 24）该列为 NaN，首跑被 S4 硬断言拦停（未产出任何判定数字）。`diag_nan.py` 实测落盘 `out/nan_diag_volume.json` / `nan_diag_amount.json`：**每口径恰 4 行 / 1,686,328（0.00024%），全部可归因为 `ret_lag24`**。S4 改为「NaN 行必须逐行归因为 `ret_lag24` 且份额 ≤1e-4，否则即停」，判定行集**保持与 E014 逐行相同**（LightGBM 原生处理缺失走默认分支）——不做非对称剔行，遵 D045 第 5 条。判据 C1 的表达式、门槛、臂设计一字未动。
  2. 新增两个**只读验证脚本**（`diag_nan.py`、`verify_join.py`）：前者是 D044 第 1 条要求的点验落盘，后者把 `col_lag0 / ma24 / ewma94` 与 E014 pair 帧逐位对拍（6 币全 OK）。两者都不产生判据数字。
  3. `DatetimeIndex.dayofweek` → `day_of_week`（pandas 4 弃用告警），取值不变。

- **C1 四项全过**：Δv = **+4.889pp**（门槛 +2.0pp）、Δbacc = **+4.326pp** > 0、Δpooled = **+4.906pp** > 0、amount 口径 Δa = **+5.086pp** > +2.0pp ⇒ `verdict_c1 = positive_model_adds_direction`。

- E1：增益几乎全部落在「当前成交量水平 + 自身 EWMA/MA 锚」这一族上，收益率组贡献可忽略。

## 4. 结论

- **一句话：阳性——在与 E014 完全同一张 OOS 考卷上，默认参数 LightGBM 回归把小时环比成交量方向从最强零训练基线 62.38% 提到 67.27%（+4.89pp，两口径 / bacc / pooled / 68-69 币同向，CI [+4.57, +5.13]pp），但 70% 目标仍未达成。**
- 对用户原问题的直接回答：70% 与最强基线差 7.6pp（E014）→ 现在差 **2.7pp**；这 2.7pp 不在「调参」能填的范围里（D044 冻结），需要新变量——特征时间尺度、标签语义（如同时段对齐而非环比）、或蒸馏 / 更大模型（torch 新依赖须另行授权）。DCKD 作者声称的 73.1%（E2）与本数**不可直接比**：任务是东京股票、标签是「今日 9 点 vs 昨日 9 点」，且未公开基率与混淆矩阵。
- 适用边界：crypto 69 USDT 1h、OOS 2024-01~2026-11-08 与主线同段（**已见数据复判，不是独立业绩**）；标签 = 小时环比方向；模型 = 默认 100 棵树、单 seed、未调参；4 个晚上市币零训练行走原生缺失分支（剔除后读数不变）；幅度侧同时优于 persistence（报告项）。
- **蒸馏未做**（预注册显式推迟）。C1 阳性成立，是否开 torch 线由用户授权决定，不在本实验范围内。
- 下一步候选（均需另行预注册）：①特征消融，把 +4.89pp 归因到组；②标签口径稳健性（同时段 vs 环比）；③蒸馏 / 概率输出线；④把 67.27% 与主线波动率模型并列，判断是否值得接入下游用途。
